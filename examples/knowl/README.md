# 知识工程实验室

## 可编码率

### 定义

可编码率 = 得分 ≥ 4 分的规则数 ÷ 总规则数

### 评分标准

| 分数 | 含义 | 是否可编码 |
|------|------|-----------|
| 5 | 直接可编码 | 是 |
| 4 | 微调后可编码 | 是 |
| 3 | 需补充信息 | 否 |
| 2 | 模糊，需重写 | 否 |
| 1 | 无法编码 | 否 |

阈值设为 4 分：3 分以下（需补充信息、模糊、无法编码）在实际编码时都会卡住，只有 ≥ 4 分的规则可以不经文档修改直接或微调后转换为代码。

### 统计口径

- **分子**：5 分 + 4 分规则的数量
- **分母**：所有被评估的规则总数
- **单位**：百分比

## 工作流程

### 知识蒸馏管线

```
Assets → Data → Code → Docs
```

1. **Assets** — 从章程/手册/教程/档案中提取规则，整理为结构化资产文件
2. **Data** — 设计业务实体 schema，逐条标注规则的可编码性分数
3. **Code** — 将 ≥ 4 分的规则实现为可执行代码，编写测试验证
4. **Docs** — 汇总评分结果，记录编码中发现的文档模糊点

### 文档改进反馈

编码过程中发现的模糊点（得分 ≤ 2 的规则）应记录出处和改进建议，反馈到对应文档仓库的 Issue，驱动上游改进。
