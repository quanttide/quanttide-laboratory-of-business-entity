# 商务拓展职能成熟度实验报告

## 管线回顾

```
Assets(4份) → Data(schema+rules+samples) → Code(calculator+tests) → Docs(scores+findings)
```

## 做了什么

1. **Assets**：从章程、手册、教程、档案中提取报价相关规则，整理为结构化的资产文件
2. **Data**：设计报价业务实体 schema，标注 15 条规则的可编码性，用教程案例作为样本数据
3. **Code**：用 Python 实现报价计算引擎，8 个测试全部通过
4. **Docs**：产出可编码性评分表和编码模糊点清单

## 学到了什么

### 核心发现：可编码率 53%

15 条规则中 8 条可直接编码（5 分），7 条因模糊或缺失无法编码。这意味着当前文档体系中有约一半的规则已经清晰到可以直接翻译为代码，另一半需要改进。

### 文档质量度量

可编码性评分提供了一个客观的文档质量度量：**章程/手册/档案的质量 = 可编码性得分**。5 分的规则说明文档清晰；1-2 分的规则说明文档有改进空间。这不是在批评文档，而是在为文档改进指引方向。

### 知识蒸馏管线的可行性

Assets → Data → Code → Docs 管线可行。每一步都暴露了上游的问题：
- 结构化时发现"保本线"未定义
- 编码时发现资深/中级人员定价缺失
- 评估时发现稀缺性评估无量化标准

这些问题在纯文本阅读时容易被忽略，但在编码时变得不可回避——**这就是治理即代码的价值**。

- 中期：扩展报价工具功能（审批流模拟、报价单模板生成）
