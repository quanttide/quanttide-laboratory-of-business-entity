# p01: 两院制议事机制

验证公司议事体系的可执行性。

## 政体模型：君主立宪制（早期）

创始人是"君主"，公司实行君主立宪制。借鉴英国立宪早期模式：

- 创始人是大股东和实际控制人，两院的权力由创始人让渡
- 上议院（股东代表大会）权力压倒下议院
- 章程已授权的事项由上议院或下议院按程序处理
- 章程**未授权**的事项，默认由创始人直接行使（君主保留特权）
- 一票否决权是创始人特权的一个子项，而非全部

### 创始人特权行使路径

章程将日常治理事项授权给两院，几乎无条款授权创始人直接行使。创始人的直接行使权来自于**君主保留原则**——章程未授权的事项，默认为创始人直接行使。

因此两条路径的本质是：

| 路径 | 流程 | 性质 | 示例 |
|------|------|------|------|
| **通过上议院** | 创始人提交 → 上议院审议 → 上议院表决 → 创始人确认 → 记录 | 创始人**选择**将事项提交上议院审议，获取集体决策意见 | 涉及重大利益但不属于紧急事态的事项，创始人希望引入审议程序 |
| **直接行使** | 创始人判定 → 创始人行使 → 记录 | 章程未授权事项的默认路径，创始人是独立决策者 | 两院僵局、治理真空、紧急事态、章程未预见的其他事项 |

两条路径的核心区别：通过上议院**有审议环节**，创始人是最终确认者；直接行使**无审议环节**，创始人是独立决策者。前者是创始人主动引入的程序，后者是默认状态。两者均须形成书面记录，但审议记录有无是区分关键。

选择依据：**默认直接行使，创始人可选择将事项提交上议院审议。**

### 与一票否决权的关系

一票否决权是创始人多项特权之一。根据场景不同，可选择通过上议院行使或直接行使。

## 场景

### 下议院（公司代表大会）
- 代表选举：各业务域/职能域按席位分配规则选举代表
- 议案审议：代表提出议案，经审议后进入表决
- 表决机制：简单多数 / 三分之二多数
- 罢免程序：对不履职代表的罢免流程

### 上议院（股东代表大会）
- 立宪权：制定和修改章程的提案 → 审议 → 表决
- 司法权：裁决章程争议的受理 → 审理 → 裁决
- 创始人部分特权通过上议院行使
- 议事记录归档

### 创始人特权
- **章程未授权事项**：直接行使，视为君主保留权力
- **一票否决权**：合规风险 / 战略偏离 / 两院僵局触发行使
- **直接发布权**：在章程未明确禁止的范围内直接发布指令
- **其他保留特权**：根据章程规定保留的其他未让渡权力
- 行使流程：触发 → 判定 → 行使 → 记录
- 所有特权行使均不得委托他人

## 验收标准

- [ ] 政体模型（君主立宪制）定位清晰，权力来源明确
- [ ] 两院职权划分清晰，上议院权力压倒下议院
- [ ] 下议院选举、审议、表决流程完整可执行
- [ ] 上议院立宪与司法流程完整
- [ ] 创始人特权大于一票否决权，包含多项子特权
- [ ] 每项特权的行使路径明确（通过上议院 vs 直接行使）
- [ ] 通过上议院行使时有完整的审议记录（上议院审议 + 表决 + 创始人否决）
- [ ] 直接行使时无审议环节，创始人是独立决策者
- [ ] 两种路径均包含：触发 → 判定 → 行使 → 记录
- [ ] 审议记录的有无是区分两种路径的核心标志
- [ ] 章程未授权事项默认为创始人直接行使
- [ ] 存在不得委托他人的限制机制
- [ ] 所有特权行使形成书面记录，包含时间、事由、依据、结果
