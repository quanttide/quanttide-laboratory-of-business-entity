# 蓝图：大数据导论实践课

本蓝图是《量潮课堂大数据导论实践课任务书》的结构化拆解，将原始需求分解为顺序执行的工作流步骤，同时定义各环节涉及的数据模型与配置契约。

## 一、数据模型

### 1.1 category — 商品分类表

分类采用三级树形结构（参考国家标准分类编码），每个分类有唯一编号、名称、所在层级、父分类引用，以及在 CPI 计算中的权重。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| code | INT | 主键，非空 | 分类编号 |
| name | VARCHAR(50) | 非空 | 分类名称 |
| weight | DECIMAL(8,4) | — | CPI 计算权重，同一层级的所有分类权重之和为 1 |
| hierarchy | INT | 非空 | 分类层级：1 = 一级，2 = 二级，3 = 三级（叶子） |
| parent | INT | 外键 | 父分类编号，顶级分类为 NULL |

### 1.2 product — 商品表

记录模拟电商平台上的所有商品，每个商品归属一个叶子分类，拥有基础价格和该分类内的权重。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| product_id | INT | 主键，非空 | 商品唯一标识（12 位随机数） |
| category_id | INT | 外键，非空 | 所属叶子分类编号，引用 category 表 |
| name | VARCHAR(50) | — | 商品名称 |
| weight | FLOAT | — | 在所属分类内的权重，同分类商品权重之和为 1 |
| price | DECIMAL(12,2) | >= 0 | 商品基础价格（单位：元） |

### 1.3 price — 日价格表

每条记录表示某个商品在某一天的价格。日价格由数据生成器按照价格变动计划产生，每天的增量写入一个独立的 CSV 文件。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| date | DATE | 联合主键，非空 | 价格记录日期（精确到天） |
| product_id | INT | 联合主键，外键，非空 | 商品编号，引用 product 表 |
| price | DECIMAL(12,2) | >= 0 | 当日价格（单位：元） |

## 二、配置契约

### 2.1 运行环境配置

系统支持本地开发环境和生产云环境两套配置，通过环境变量 `APP_ENV` 和 `IS_LOCAL` 切换：

| 配置项 | 本地 (dev) | 生产 (prod) |
|--------|-----------|-------------|
| 对象存储 | MinIO (localhost:9000) | 阿里云 OSS |
| 数据库 | ClickHouse 本地实例 | 阿里云 ClickHouse |
| 连接加密 | 关闭 | SSL/TLS 加密 |
| 证书验证 | 不验证 | 生产环境验证 |

### 2.2 对象存储配置

| 配置项 | 说明 |
|--------|------|
| OSS_ENDPOINT | 对象存储访问域名 |
| OSS_BUCKET | 存储桶名称 |
| OSS_ACCESS_KEY | 访问密钥（生产环境通过环境变量注入） |

### 2.3 ClickHouse 配置

| 配置项 | 说明 |
|--------|------|
| CH_HOST / CH_PORT | ClickHouse 连接地址与端口 |
| CH_USER / CH_PASSWORD | 认证凭据 |
| connect_timeout | 连接超时时间（生产 30s，本地 60s） |
| max_execution_time | 查询最大执行时间（180s） |

### 2.4 模拟数据生成参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| SIMULATE_DAYS | 365 | 模拟天数 |
| SIMULATE_CATEGORIES | 食品、家居、数码、服饰 | 四个一级分类 |
| SIMULATE_ITEMS_PER_CAT | 50 | 每个分类每日有效商品数 |
| CATEGORY_WEIGHTS | 0.4 / 0.2 / 0.2 / 0.2 | 一级分类 CPI 权重 |

### 2.5 算法配置

| 配置项 | 可选值 | 说明 |
|--------|--------|------|
| base_mode | auto / monthly / fixed | 基期模式：首日自动 / 每月首日 / 固定日期 |
| 指数类型 | cavallo / tmall | 几何平均法 / 加权平均法 |
| 链式模式 | chain | 每期基于上期环比推算，保持指数连续性 |

## 三、存储契约

### 3.1 OSS 存储适配

对象存储连接器自动适配本地 MinIO 和生产阿里云 OSS。启动时检测运行环境，本地环境自动创建 Bucket。

上传和下载均以 DataFrame 为中心：Python 程序将 DataFrame 序列化为 CSV 写入对象存储，或从对象存储拉取 CSV 还原为 DataFrame。

### 3.2 ClickHouse DDL

三张核心表在 ClickHouse 中对应以下建表语句：

- category 表使用 `MergeTree` 引擎，以 `category_id` 为排序键，字段包括 `category_id`(UInt32)、`name`(String)、`weight`(Float64)、`timestamp`(DateTime)。
- item 表使用 `MergeTree` 引擎，以 `item_id`(String) 为排序键，字段包括 `item_id` 和 `category_id`(UInt32)。
- price 表使用 `MergeTree` 引擎，以 `(date, item_id)` 为复合排序键，字段包括 `date`(Date)、`item_id`(String)、`price`(Float64)。

### 3.3 数据文件路径约定

| 文件 | 路径 | 格式 |
|------|------|------|
| 分类数据 | data/categories.csv | CSV，字段：category_id, category, weight, hierarchy, parent |
| 商品数据 | data/products.csv | CSV，字段：product_id, category_id, name, weight, price |
| 每日价格 | data/daily_price/daily_prices_YYYYMMDD.csv | CSV，字段：product_id, date, price |

## 四、工作流

### 步骤一：数据生成

基于分类、商品、价格三级数据模型，生成模拟电商数据集。

分类数据由随机权重算法生成：四个一级分类的权重分别设为 0.4、0.2、0.2、0.2，同分类内商品权重归一化使总和为 1。

商品数据从叶子分类中生成，每个叶子分类分配固定数量的商品，商品初始价格在基础价格的 ±30% 范围内随机波动。

每日价格数据由价格生成器模拟一年的走势：每个商品在一开始就确定全年的价格变动计划（以 0.9~1.1 倍随机系数调整），每日按计划生成价格文件。同时，每天的商品池有小比例更替（1%~2% 的上新/下架），模拟真实电商货架变动。

这一步的输入是模拟参数配置，输出是 CSV 格式的分类表、商品表和 365 天每日价格文件，写入本地 data 目录。

### 步骤二：数据导入

将步骤一产出的本地 CSV 数据集上传至对象存储，并导入 ClickHouse。

在对象存储中创建 Bucket 并配置访问权限，然后上传三个 CSV 文件。随后初始化 ClickHouse 连接，创建 category、item、price 三张表，将 CSV 数据批量写入。

本地环境使用 MinIO 作为对象存储后端，生产环境使用阿里云 OSS。连接侧自动检测环境，本地不启用 SSL 加密，云端强制加密连接。

这一步的输入是步骤一的 CSV 产出，输出是对象存储中已就绪的数据文件和 ClickHouse 中已建表的三张数据表。

### 步骤三：数据清洗

对导入的价格数据进行清洗，排除异常值，确保后续计算的准确性。

清洗规则包括：过滤空价格和零/负价格、将日期列转换为 ClickHouse Date 类型、商品 ID 统一为大写并去空格、分类权重裁剪到 [0, 1] 区间。

清洗完成后还需进行字段适配：分类权重归一化使各层级权重之和为 1，价格统一为 Decimal(12,2) 精度。

这一步依赖步骤二的导入结果，输入是 ClickHouse 中的原始数据表，输出是清洗后的干净数据。

### 步骤四：价格指数计算

基于清洗后的数据，实现两种价格指数算法。

Cavallo 指数采用几何平均法：对每个商品，计算报告期价格与基期价格的比率，取所有商品的几何平均数（即对数均值的指数），再乘以 100 作为指数值。

Tmall 指数采用加权平均法：先计算每个分类的平均价格，再按分类权重加权聚合。与 Cavallo 指数的区别在于它在分类层面聚合，而非商品层面。

两种指数均支持三种基期模式：
- auto：以数据首日为固定基期，往后所有日期与首日比较
- monthly：每月首日作为新基期，仅比较当月范围内的数据
- fixed：以指定日期作为固定基期

计算结果写入 data 目录下的 CSV 文件（cavallo_index.csv 和 tmall_index.csv），每行包含日期、指数值和基期日期。

这一步依赖步骤三的清洗产出，输入是干净的数据表，输出是指数计算结果的 CSV 文件。

### 步骤五：可视化

将步骤四产出的指数时间序列转化为趋势图。

支持 matplotlib 和 plotly 两种渲染引擎。matplotlib 输出静态 PNG 或 JPG，plotly 输出可交互的 HTML。生产环境可接入 BI 工具（如 QuickBI），按模板生成报告页。

生成的图表以日期为横轴、指数值为纵轴，折线图展示日度 CPI 随时间的变化趋势。

这一步依赖步骤四的输出，输入是指数 CSV 文件，输出是趋势图（PNG / HTML）。

### 步骤六：测试与验证

对全流程进行验证，确保计算结果的正确性。

单元测试覆盖两个方面：
- 数据生成器测试：验证生成的分类数据和商品数据字段完整、权重归一化正确
- CPI 计算器测试：验证数据加载、指数计算和可视化输出功能正常

集成测试检查商品覆盖率达到 80% 以上、异常过滤准确率达到 95%（可选）。测试数据使用手工构造的小规模 CSV 数据集。

这一步的测试范围覆盖步骤一至步骤五，输入是测试数据，输出是测试报告。

### 步骤七：文档与报告

汇总所有前置步骤产出的分析数据和代码成果，撰写面向教学团队提交的最终交付文档。

设计文档需包含需求分析、表结构设计（含三张核心表与 ClickHouse DDL）、核心 Python 代码逻辑、核心 SQL 逻辑。

实践报告需包含需求分析、表结构设计、SQL 算法与关键语句分析、详细代码设计、运行结果截图、心得体会。
