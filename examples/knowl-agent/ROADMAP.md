# 执行方案 — 知识库质量反向检测

## 检测维度

| 维度 | 检测内容 | 检测方式 | 反馈给人类 |
|------|---------|---------|-----------|
| **知识建模** | AI 能否从知识库中提取出清晰的概念模型、关系模型和规则模型？模型是否有歧义、冗余或缺失？ | 自动抽取知识图谱 / 本体模型，评估模型清晰度与覆盖度 | 展示抽取出的模型结构，标记模糊或断裂处 |
| **知识融合** | 不同来源、不同表述的知识在融合后是否一致？是否存在同名异义、异名同义、矛盾断言？ | 实体对齐、冲突检测、冗余检测 | 列出冲突项和冗余项，标注置信度 |
| **结构自洽性** | 知识库是否有自我引用的规则？规则之间是否冲突？ | 元规则匹配 | 高亮矛盾规则对 |
| **规范遵循度** | 知识是否遵循自身声明的写作规范？ | 样式一致性扫描 | 定位违规段落 |
| **完备性** | 必备的结构要素是否缺失？ | 模板匹配 | 列出缺失要素清单 |

## 工作流程

### 第一步：获取知识库的元规则

从知识库中提取描述"知识应该怎么写"的规则。如果存在这样的元规则，将其解析为检测基准。

**信号**：
- 存在类似"写作章程""格式规范""AGENTS.md"的文件
- 有明确的条款式规则（应当/不得/可以）
- 有文件命名约定、目录结构说明

**负面信号**：
- 没有任何元规则 → 知识库质量不可控，每条知识依赖个人经验
- 元规则自相矛盾 → 规则未被真正执行
- 元规则与知识库实际内容不符 → 规则已过时或从未被遵守

### 第二步：执行知识工程检测

#### 知识建模检测

- **概念抽取**：从知识文本中提取核心概念及定义，构建概念图谱
- **关系抽取**：识别概念间的关系（is-a, part-of, causal, etc.），评估关系密度与清晰度
- **规则抽取**：提取条件-结论形式的规则，检查规则链是否完整
- **模型评估**：检查模型是否存在循环定义、未定义概念、孤立节点
- **输出**：知识模型结构图 + 模型质量问题清单

#### 知识融合检测

- **实体对齐**：识别不同条目中指向同一实体的表述，标注不一致处
- **冲突检测**：检测对同一属性的矛盾声明（如 A 的父类是 B vs A 的父类是 C）
- **冗余检测**：检测内容高度重叠的知识条目
- **输出**：冲突报告 + 冗余报告 + 对齐建议

#### 结构格式检测

- **结构检测**：每份知识是否遵循统一的结构框架（总则→主体→附则）？
- **格式检测**：标题层级是否克制？分隔线、列表、加粗是否滥用？
- **用语检测**：规范用语（应当/不得/可以）是否一致？同一概念是否使用同一名称？
- **条款检测**：条款编号是否连续？必备条款（制定依据、目的、适用范围）是否完整？

### 第三步：生成可交互的质量报告

对每个检测项输出：

- **通过** ✅ — 无需人工介入
- **警告** ⚠️ — 建议人工复核，附原因和上下文
- **违规** ❌ — 必须人工修改，附具体位置和修改建议

报告结构：
```
知识库质量报告
├── 知识建模检测 (通过 3, 警告 1, 违规 0)
├── 知识融合检测 (通过 2, 警告 2, 违规 1)
├── 结构自洽性 (通过 1, 警告 0, 违规 0)
├── 规范遵循度 (通过 4, 警告 1, 违规 0)
└── 完备性检测   (通过 2, 警告 0, 违规 1)
```

## 人类反馈闭环

本智能体的最终输出**不是自动修正**，而是给人提供可操作的决策信息：

1. **展示**：以结构化报告和可视化方式呈现检测结果
2. **标记**：在原文中标注问题位置（行号、段落）
3. **建议**：对每个问题给出 1–2 条修改建议（但不自动执行）
4. **追踪**：记录已确认和已修复的问题，支持增量检测
