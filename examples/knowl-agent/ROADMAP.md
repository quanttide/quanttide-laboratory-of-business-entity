# 执行方案 — 知识库质量反向检测

## 检测维度

| 维度 | 检测内容 | 检测方式 | 反馈给人类 |
|------|---------|---------|-----------|
| **知识抽取** | 能否从知识文本中抽取出结构化知识要素（实体、关系、属性、规则、术语定义）？ | NLP 解析 + 模式匹配，从文本中提取知识三元组和定义句 | 展示抽取出的知识要素清单，标记未解析段落 |
| **知识建模** | 抽取出的知识能否构成清晰、一致、完备的概念模型和规则模型？模型是否有歧义、冗余、循环或缺失？ | 构建知识图谱 / 本体模型，分析模型结构质量 | 展示模型结构图，标记模糊、断裂、孤立、循环处 |
| **知识融合** | 不同文件的知识在融合后是否一致？是否存在同名异义、异名同义、矛盾断言、冗余定义？ | 跨文件实体对齐、冲突检测、冗余检测 | 列出冲突项和冗余项，标注置信度和来源 |

## 执行阶段

### 预备阶段：知识领域发现

**目标**：在开始抽取和建模之前，先扫描知识库识别其所涵盖的知识领域。

同一知识库可同时包含多个领域。AI 通常会在人的影响下使用某个领域的视角来发掘本体——因此需要先识别出有哪些视角可选。

**步骤**：

1. **领域扫描**：遍历所有文件，根据词汇特征、引用关系、内容主题初步判断涉及的领域
2. **领域分类**：为每个文件标注所属领域（一个文件可跨多个领域）
3. **视角声明**：对每个领域声明其观察视角，避免单视角偏见

**示例**（以当前样本知识库）：

| 领域 | 特征词汇 | 涉及文件 | 视角说明 |
|------|---------|---------|---------|
| 组织管理 | 权责、流程、岗位、职责、风险 | company-representative.md, qtdata-index.md, human-resignation.md | 关注组织结构和角色关系 |
| 法学/规范 | 依据、效力、解释权、不得被解释为 | 所有文件 | 关注规范层级和义务-例外结构 |
| 文档写作 | 格式、排版、标题、列表、加粗 | docs-format.md | 关注表达形式和结构规范 |
| 数据管理 | 数据安全、个人信息、知识产权、加密 | qtdata-index.md | 关注数据治理和保护 |
| 人力资源 | 离职、辞职、交接、培训生、职级 | human-resignation.md, company-representative.md | 关注员工生命周期 |

**输出**：`domains/<domain>/domain.json` — 每个领域一个目录，包含领域定义和文件清单。

---

### 第一阶段：知识抽取（按领域）

**目标**：在每个领域内，从知识库文件中抽取出结构化的知识要素。

抽取方法与原方案一致，但按领域分目录管理，避免跨领域要素混在一起。

**输出**：`domains/<domain>/extraction/` — 包含术语、实体、关系、规则等抽取结果。

---

### 第二阶段：知识建模（按领域）

**目标**：在每个领域内，通过该领域的视角发现本体和范畴。

#### 本体发现

一个领域下可发现多个本体。本体是领域内反复出现的概念结构。

**示例**（组织管理领域）：

| 本体 | 抽象模式 |
|------|---------|
| 权责 | `<主体> 拥有 <职权> → 行使时负有 <义务>` |
| 流程 | `<流程> = <阶段序列>` |
| 风险-控制 | `<风险> → <影响> → <控制措施>` |
| 资格-条件 | `<条件满足> → <获得资格> → <条件丧失> → <资格终止>` |

**示例**（法学/规范领域）：

| 本体 | 抽象模式 |
|------|---------|
| 规范层级 | `<上位规范> → 授权/派生 → <下位规范>` |
| 义务-例外 | `<规则> + <例外条件>` |
| 效力声明 | `经 <机构> <行为> 后生效，修改亦同` |

#### 范畴发现

范畴是跨本体或跨实体的关系。在同一领域视角下，范畴连接不同本体。

**输出**：`domains/<domain>/ontologies.json` + `domains/<domain>/categories.json` + `domains/<domain>/instances.json`

---

### 第三阶段：知识融合（跨领域）

**目标**：跨领域检测知识的一致性和冲突。

#### 3.1 跨领域对齐

同一术语在不同领域中可能有不同定义。例如：

| 术语 | 组织管理视角 | 法学视角 |
|------|------------|---------|
| 章程 | 公司治理文件 | 规范性文件 |
| 效力 | 执行力 | 生效条件 |

#### 3.2 冲突检测

| 检查项 | 检测逻辑 |
|--------|---------|
| 同名异义 | 同一术语在不同领域中定义不同 |
| 异名同义 | 不同术语在不同领域中指向同一概念 |
| 矛盾断言 | 对同一实体的同一属性在不同领域中有矛盾声明 |
| 引用断裂 | 跨文件引用指向不存在的章节、条款或文件 |

**输出**：`data/fusion-report.json`

---

### 第四阶段：报告与追踪

#### 严重级别

```
P0 — 阻断性：循环定义、模型断裂，须立即修复
P1 — 严重：未定义概念、同义冲突，建议本轮修复
P2 — 一般：冗余定义、孤立节点，可推迟处理
P3 — 建议：模型覆盖度不足，可纳入后续迭代
```

#### 增量检测

后续检测只扫描：
1. 新增文件
2. 有修改的文件
3. 与前次检测结果存在关联的问题
