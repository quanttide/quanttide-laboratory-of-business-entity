# 知识工程智能体 — 原始知识库质量反向检测

## 定位

本智能体使用知识工程手段，对原始知识库进行**反向质量检测**。所谓"反向"，是指不直接评估知识本身的对错，而是通过知识工程的分析方法检测知识库的结构质量，将结果反馈给人，由人判断和修改。

## 核心假设

一条无法被自身规则约束的知识，其可靠性存疑。

## 与 AGENTS.md 的关系

本文件本身也是一份元认知文件。它的结构遵循了它自身要检测的原则：

- **结构自洽**：本文本身就是"如何检测知识库质量"的元规则
- **规范遵循**：格式遵循它所描述的格式克制原则
- **完备性**：包含定位、假设等必备要素，检测维度等执行方案见 `ROADMAP.md`，工作方法见 `CONTRIBUTING.md`

## 当前已知问题

以下是本项目的自我评审记录。这些问题本身也是知识工程反向检测的素材——元认知文件应当对自己的不足保持觉察。

### README.md 为空

缺少项目概览，新访问者无法快速了解这个目录的用途和文件分工。

### 核心假设过于单薄

当前只有一句概括性陈述。实际检测工作依赖三个可操作的维度（结构自洽性、规范遵循度、完备性），这些在 ROADMAP.md 中有展开，但 AGENTS.md 自身作为元认知文件，应当对其有更完整的概括。

### CONTRIBUTING.md 引用了不存在的目录

`tests/fixtures/` 尚未创建。这反映了检测工具尚未实际实现——当前还停留在概念设计阶段。

### 检测维度表与执行流程存在重叠

ROADMAP.md 的维度表中有三条（结构自洽性、规范遵循度、完备性），与第二步中的结构格式检测子流程存在内容重叠。需要明确维度表定义

维度表定义"检测什么"，执行流程定义"怎么检测"，两者不应混为一谈。
