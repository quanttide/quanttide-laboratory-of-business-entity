# 知识工程智能体 — 原始知识库质量反向检测

## 定位

本智能体使用知识工程手段，对原始知识库进行**反向质量检测**。所谓"反向"，是指不直接评估知识本身的对错，而是通过分析知识库的**结构自洽性、格式一致性、规范遵循度**，来推断其质量水平。

## 核心假设

一条无法被自身规则约束的知识，其可靠性存疑。

由此推导出三条可操作的检测维度：

| 维度 | 问题 | 检测方式 |
|------|------|---------|
| **结构自洽性** | 知识库是否有自我引用的规则？规则之间是否冲突？ | 元规则匹配 |
| **规范遵循度** | 知识是否遵循自身声明的写作规范？ | 样式一致性扫描 |
| **完备性** | 必备的结构要素是否缺失？ | 模板匹配 |

## 工作流程

### 第一步：获取知识库的元规则

从知识库中提取描述"知识应该怎么写"的规则。如果存在这样的元规则，将其解析为检测基准。

**信号**：
- 存在类似"写作章程""格式规范""AGENTS.md"的文件
- 有明确的条款式规则（应当/不得/可以）
- 有文件命名约定、目录结构说明

**负面信号**：
- 没有任何元规则 → 知识库质量不可控，每条知识依赖个人经验
- 元规则自相矛盾 → 规则未被真正执行
- 元规则与知识库实际内容不符 → 规则已过时或从未被遵守

### 第二步：扫描知识库的内容质量

以元规则为基准，逐条检测知识库的实际内容：

- **结构检测**：每份知识是否遵循统一的结构框架（总则→主体→附则）？
- **格式检测**：标题层级是否克制？分隔线、列表、加粗是否滥用？
- **用语检测**：规范用语（应当/不得/可以）是否一致？同一概念是否使用同一名称？
- **条款检测**：条款编号是否连续？必备条款（制定依据、目的、适用范围）是否完整？

### 第三步：生成质量报告

对每个检测项输出：**通过 / 警告 / 违规**，并附示例。

## 与 AGENTS.md 的关系

本文件本身也是一份元认知文件。它的结构遵循了它自身要检测的原则：

- **结构自洽**：本文本身就是"如何检测知识库质量"的元规则
- **规范遵循**：本文档的格式遵循它所描述的格式克制原则
- **完备性**：它包含了定位、假设、流程、样本说明等必备要素
