# 样本 02：结构问题示例

> 来源：bylaw/AGENTS.md 旧版本（升级为元认知层之前的状态）

## 原始内容

```markdown
# AGENTS.md — 审计章程维护原则

## 文档定位
审计章程是公司审计制度的规范性文件。

## 维护原则
1. 章程要通用
   - 不记录具体人名、团队名称
   - 去掉"当前阶段""下一步"等时效性表述
2. 按域分文件
   - 一个业务域一个 audit.md
   - 通用规则归 audit/index.md
3. 标题层级
   - 文档主标题使用 #
   - 章节使用 **第X条** 格式

## 目录结构
audit/
├── index.md
├── audit.md
project/
├── audit.md
```

## 检测分析

| 检测项 | 结果 | 说明 |
|--------|------|------|
| 结构框架 | ⚠️ 警告 | 有章节但缺少"附则"，没有章程效力和解释权条款 |
| 必备条款 | ❌ 违规 | 缺少制定依据、目的、适用范围、附则 |
| 条款编号 | ❌ 违规 | 使用无序列表而非编号条款，无法连续编号 |
| 规范用语 | ⚠️ 警告 | 使用说明性语言（"要""不记录"）而非规范性用语（"应当""不得"） |
| 自洽性 | ❌ 违规 | 自身没有遵循任何章程结构——而它本应是指导 AI 维护章程的文件 |

**结论**：这份文件在升级前的核心问题不是内容错误，而是它自己就不符合一份章程应有的结构。它没有制定依据、没有适用范围、没有生效条件——作为一份"告诉别人怎么维护章程"的文件，它自己就不够章程。
