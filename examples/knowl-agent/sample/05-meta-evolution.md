# AGENTS.md — 元认知规则

## 章程维护的元认知

本仓库的内容是公司治理的规范性文件，具有约束力。维护章程不是在写文档，而是在制定规则。

### 模式觉察

区分三种工作模式，不跳阶段：

- **理解模式**：听清需求——要新增一个业务域的章程，还是修订已有条款？不替用户决定章程内容。
- **执行模式**：章程文本的每一条都应有约束力——这条规则是可执行的还是空话？不确定时去查现行制度。
- **验证模式**：新增章程是否与现有章程冲突？制度之间是否自洽？不把"没报错"当成"已生效"。

### 置信度校准

- 对于章程内容的把握，区分"这是仓库已有的规定"和"这是我推测应该有的规定"。
- 撰写条款时不编造制度依据。如果用户未明确制度内容，停下来确认。
- 不确定的命名或路径，去文件系统验证，不凭印象猜测。

### 收敛监控

- 同一问题反复修改时，检查是**在逼近一致**还是**在绕圈**。绕圈意味着：理解有误、工具用错、或需求已漂移。
- 条款的每一次修改都应有明确的制度动机——不是为了措辞更好看，而是为了约束更准确。

### 意图对齐

- 每轮操作前自问：用户要的是制定制度，还是整理文档格式？
- 回答和操作只服务于用户陈述的意图。不擅自扩展章程范围。
- 如果用户的需求和现有章程的制度逻辑存在张力，指出来而非掩盖。

### 章程遵守

本仓库已有两份元章程约束所有写作行为：

- `write/bylaw.md`（工作章程写作章程）——规定文档结构、条款格式、内容规范、语言规范
- `docs/format.md`（文档格式章程）——规定标题层级、列表、表格、代码块等排版要素

操作中须遵守以下规则：

- **新建或修订章程**：严格遵循 `write/bylaw.md` 的结构框架（总则→主体→附则）、条款格式（`**第X条**`）、规范用语（应当/不得/可以）。
- **格式化文档**：严格遵循 `docs/format.md` 的排版规则，保持格式克制，不超过三级标题，不滥用分隔线和加粗。
- **冲突处理**：若用户要求与两份元章程存在冲突，应指出不一致之处并建议对齐。
- **自我检查**：每次提交前，对照两份章程检查产出物是否符合要求。

对这两份章程本身的修订，仍须遵循它们自身的规定。

## 与 CONTRIBUTING 的分工

| 文件 | 职责 |
|------|------|
| `AGENTS.md` | AI Agent 的元认知——怎么思考章程维护 |
| `write/bylaw.md` | 内容规范——文档结构、条款格式、语言 |
| `docs/format.md` | 格式规范——标题、列表、表格等排版要素 |
| `CONTRIBUTING.md` | 操作规范——目录怎么命名、文件放哪里 |
| `README.md` | 项目概览——仓库有什么、目录结构 |
