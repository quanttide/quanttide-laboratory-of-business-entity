# 样本 05：元认知文件的演化

> 来源：bylaw/AGENTS.md 的版本变迁

## 背景

AGENTS.md 是 AI Agent 的元认知文件——它告诉 AI 助手应该**怎么思考**。但这个文件经历了两次重大重构才找到自己的定位。

## 第一阶段：操作手册混入

最初，AGENTS.md 写的是具体操作细节：

```
文件命名用 snake_case
标题层级不超过三级
审计章程统一命名为 audit.md
```

问题：这些内容与 CONTRIBUTING.md 重复，且不适合放在元认知层。

## 第二阶段：元认知升级

重构后，操作细节被搬走，元认知层留下了真正核心的东西：

```markdown
### 模式觉察
区分三种工作模式，不跳阶段：
- 理解模式：听清需求，不替用户决定
- 执行模式：每一条都应有约束力
- 验证模式：制度之间是否自洽？

### 置信度校准
区分"这是仓库已有的规定"和"这是我推测应该有的规定"。
撰写条款时不编造制度依据。

### 收敛监控
同一问题反复修改时，检查是在逼近一致还是在绕圈。

### 章程遵守
新建或修订章程，须严格遵循 write/bylaw.md 和 docs/format.md。
```

## 检测分析

| 检测项 | 结果（第一阶段） | 结果（第二阶段） |
|--------|-----------------|-----------------|
| 定位清晰 | ❌ 身份模糊——既像操作手册又像认知指南 | ✅ 明确为"AI Agent 的元认知" |
| 内容不重叠 | ❌ 与 CONTRIBUTING.md 重叠严重 | ✅ 操作细节已搬走，各自独立 |
| 结构自洽 | ⚠️ 无制定依据、无适用范围 | ✅ 遵循 write/bylaw.md 的结构 |
| 可执行性 | ⚠️ 操作细节可执行但层级不对 | ✅ 元认知规则可引导 Agent 行为 |

## 经验

一份元认知文件如果写满了操作细节，它就失去了元认知的作用。**当把操作细节分走后，剩下的反而是最核心的东西——思维方式本身。** 这个发现本身就是知识工程反向检测的典型案例：通过分析文件定位与内容的不匹配，发现了结构性问题。
