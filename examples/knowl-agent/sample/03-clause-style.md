# 样本 03：规范用语对照

> 来源：bylaw/write/bylaw.md（第四章 语言规范）+ bylaws 仓库各章程实例

## 正例

```markdown
**第十六条 规范用语**
制度性内容应使用以下规范用语：

| 含义 | 用语 |
|------|------|
| 强制义务 | "应当""须""必须" |
| 禁止行为 | "不得""禁止" |
| 授权允许 | "可以""有权" |
| 推荐非强制 | "宜""建议" |

同一含义在全仓库范围内应使用同一用语，避免混用。
```

**来自实例的正例：**

```
（来自 format.md）标题层级最多使用三级，不得继续嵌套更深层级。
（来自 write/bylaw.md）条号按全文顺序连续编号，不按章重置。
（来自 connect/index.md）每位成员均拥有认知主权，不容侵犯。
```

## 误例

```markdown
**（误）** 章程的内容要通用，不要写具体人名。
**（正）** 章程内容应保持通用，不记录具体人名。

**（误）** 我们建议标题使用三级以内。
**（正）** 最多使用三级标题，不得继续嵌套更深层级。

**（误）** 记得更新 myst.yml。
**（正）** 新增业务域章程时，须同步更新 myst.yml 的 toc。
```

## 检测分析

| 检测项 | 结果 | 说明 |
|--------|------|------|
| 语气一致性 | ✅ / ❌ | 正例使用"应当/不得"形成约束力；误例使用"要/不要/建议"语气偏弱，无法作为规则执行 |
| 术语一致性 | ✅ / ❌ | 正例同一概念统一用语；误例混用"要/应当/建议"、"不要/不得/禁止" |
| AI 生成残留 | ❌ 常见 | AI 倾向使用"我们建议""请记得""最好"等弱约束用语，需要人工校正为"应当""须""不得" |
