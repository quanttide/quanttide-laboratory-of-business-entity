# 量潮科技工作章程写作章程

## 第一章 总则

**第一条 制定依据**
本章程依据本仓库历次章程维护的实践经验总结制定，旨在建立工作章程写作的标准化规范，确保各业务域章程在结构、格式、语言上保持一致性。

**第二条 目的**
为规范章程写作行为，降低维护成本，使新增章程的撰写有章可循、有例可依，特制定本章程。

**第三条 适用范围**
本章程适用于本仓库所有工作章程的新增与修订。本仓库所有工作章程——无论业务域——均须遵循本章程所规定的结构、格式与内容规范。

**第四条 章程的定位**
工作章程是公司治理的规范性文件，具有约束力。章程与操作手册的区别如下：

（一）章程规定"应当做什么、不得做什么"，操作手册说明"怎么做"；
（二）章程追求长期稳定，操作手册随流程持续更新；
（三）章程面向全员，操作手册面向特定岗位。

## 第二章 文档结构

**第五条 标准框架**
工作章程应遵循以下标准框架：

```
# 量潮科技<业务域><类型>章程

## 第一章 总则

**第X条 制定依据**
（说明依据的上位制度）

**第X条 目的**
（说明制定本章程的目的）

**第X条 适用范围**
（说明适用的主体、场景、范围）

**第X条 定义**（可选）
（对本章程使用的关键术语进行定义）

## 第二章 至 第N章 （主体章节）

（按业务逻辑组织章节，每章聚焦一个主题）

## 第N+1章 附则

**第X条 章程效力**
本章程经公司最高权力机构审议通过后生效，修改亦同。

**第X条 解释权**
本章程之解释，应遵循（基本原则）。各项条文不得被解释为……
```

**第六条 标题格式**
文档名称应遵循以下格式：

```
# 量潮科技<业务域><章程类型>章程
```

章节目录使用二级标题：

```
## 第X章 <章节名>
```

章节名使用简洁的业务术语，如"总则""业务范围""岗位与职责""服务流程""附则"。

**第七条 条款格式**
每一条款使用条号加粗格式：

```
**第X条 <条名>**
```

条名使用名词性短语，概括该条所规定的内容，如"制定依据""适用范围""服务范围""生效与修订"。

条号按全文顺序连续编号，不按章重置。

**第八条 列举格式**
条款内包含多项并列内容时，使用带括号的汉字编号：

```
（一）第一项；
（二）第二项；
（三）第三项。
```

子项可进一步拆分为带数字圆圈编号，但不超过两级嵌套。

## 第三章 内容规范

**第九条 通用性原则**
章程内容应保持通用，不记录以下内容：

（一）具体人名、团队名称；
（二）阶段性推进状态；
（三）尚未确定的计划或意向；
（四）"当前阶段""下一步""近期"等时效性表述。

**第十条 稳定性原则**
章程内容应追求长期有效，避免记载以下内容：

（一）临时性或一次性安排；
（二）可能频繁变更的操作细节；
（三）依赖特定技术或工具的流程。

操作层面的内容应归入操作手册而非章程。

**第十一条 按域分文件原则**
每个业务域一个独立文件，不混合不同域的内容在同一文件。各域的通用规则提取为总纲文件（`index.md`），各域特有的规则放在本域文件。

**第十二条 总则必备条款**
每一份工作章程的总则至少应包含以下条款：

（一）**制定依据**——说明本章程的上位制度依据；
（二）**目的**——简要说明制定本章程要解决的问题；
（三）**适用范围**——明确本章程适用的主体、业务场景或组织范围；
（四）**定义**（如需要）——对本章程使用的关键术语作出界定，避免歧义。

**第十三条 附则必备条款**
每一份工作章程的附则至少应包含以下条款：

（一）**章程效力**——规定生效条件和修改程序；
（二）**解释权**——规定解释原则，注明各项条文的限制性解释方向。

**第十四条 主体章节的排列顺序**
主体章节应遵循"从抽象到具体、从前置到后续"的逻辑顺序。推荐顺序如下：

（一）业务范围或基本原则——界定该业务域的边界和核心规则；
（二）组织架构或岗位职责——谁负责什么；
（三）流程或程序——事情怎么做、按什么顺序做；
（四）质量标准或约束条件——对输出的要求和界限；
（五）附则——生效、解释、修订。

## 第四章 语言规范

**第十五条 语体要求**
工作章程使用正式书面语，语气准确、无歧义。禁止以下表达方式：

（一）口语化表达；
（二）模棱两可的措辞；
（三）对话式或互动式表述；
（四）带有情感色彩的修饰语。

**第十六条 规范用语**
制度性内容应使用以下规范用语：

| 含义 | 用语 |
|------|------|
| 强制义务 | "应当""须""必须" |
| 禁止行为 | "不得""禁止" |
| 授权允许 | "可以""有权" |
| 推荐非强制 | "宜""建议" |
| 条件假设 | "的""时""情况下" |

同一含义在全仓库范围内应使用同一用语，避免混用。

**第十七条 定义用语**
术语定义使用以下格式：

```
（一）**术语名称**，指……
```

被定义的术语在后续条款中首次出现时，可仅使用术语名称。同一术语在全仓库范围内含义应保持一致。

## 第五章 文件与目录规范

**第十八条 目录命名**
目录名统一使用 `snake_case`（小写字母+下划线）。一个业务域一个目录，目录名对应业务域英文或拼音缩写。

**第十九条 文件命名**
文件名统一使用 `snake_case`（小写字母+下划线）。业务域总纲使用 `index.md`，各域审计章程统一使用 `audit.md`，其他文件根据内容命名。

**第二十条 目录结构维护**
新增业务域章程时，须同步完成以下操作：

（一）创建 `snake_case` 目录；
（二）在目录内创建 `index.md`（总纲）或对应章程文件；
（三）更新项目根目录 `myst.yml` 的 `toc` 添加文档索引；
（四）更新 `CHANGELOG.md`。

## 第六章 附则

**第二十一条 章程效力**
本章程自发布之日起生效。本章程适用于本仓库所有工作章程的新增与修订。已有章程与本章程不一致的，应逐步修订以符合本章程的要求。

**第二十二条 解释权**
本章程之解释，应遵循一致性之基本原则。各项条文不得被解释为禁止合理的章程创新或降低章程质量。
