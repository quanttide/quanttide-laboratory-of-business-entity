# 人机权责清单

## 元规则

| 角色 | 擅长 | 不擅长 |
|:----|:----|:------|
| 规则引擎（src/） | 确定规则——固定模式匹配、格式校验、计数、文件读写 | 模糊匹配、语义理解、做判断 |
| 智能体 | 概率模式匹配——解读信号、分析根因、做建议、补全内容 | 理解罕见意外、做组织决策 |
| 人类 | 意义与意外——理解上下文、识别异常、做组织决策 | 执行重复性操作、精确计数 |

分工不由想怎么分决定，由能力边界决定。脚本的事交给脚本，判断的事交给智能体，组织的事交给人类。

## 规则引擎

所有有确定规则的操作，无论读还是写：

| 命令 | 职责 |
|:----|:----|
| `python -m src.cli validate` | 检查四个 JSON 文件存在性和 JSON 格式合法性 |
| `python -m src.cli summary` | 统计各领域的本体、实例、关系、文件数 |
| `python -m src.cli fusion-check` | 跨领域检测：同名本体冲突、词汇交叉、引用断裂、效力主体一致性 |
| `python -m src.cli detect-domain` | 新文件词汇命中排序，推荐领域 |
| `python -m src.cli init-domain` | 创建领域目录和骨架 JSON |
| `python -m src.cli find-undefined-terms` | 扫描加粗术语对比已知定义，列出未定义项 |
| `python -m src.cli auto-fix` | 循环 validate + 补缺失骨架文件 |

边界：
- 有确定规则即可读写文件
- 不做需要概率判断的事

## 智能体

解读信号、概率匹配、做建议。所有没有 100% 确定规则但智能体能做的事：

- 编排脚本组合
- 解读输出、排查根因
- 判断未定义术语是真缺口还是假阳性
- 判断引用断裂是否需要创建 stub
- 建议效力统一方向
- 多领域命中接近时分析视角差异
- 发现深层结构缺口给人
- 写 ontology pattern 时执行自检：跨文件检查、去值测试、换源测试
- 区分常量和变量：固定结构留在 pattern，具体值写入 instances.json

不能做涉及组织权力、效力主体、人事的决策——这些标记 **【需人确认】**。

输出规范：
- 最终交付物包含做了什么、没做什么、需要人审什么
- 拿不准的判断标记 **【需人确认】**

## 人类

审核最终结果，处理意义与意外：

- 做智能体标记 **【需人确认】** 的决策
- 审核效力声明统一方案
- 对组织权力、人事、权责分歧做最终判断
- 不看中间过程
