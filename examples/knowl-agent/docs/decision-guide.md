# 三分工

| 角色 | 负责 |
|------|------|
| **规则引擎**（scripts/） | 所有有确定规则的事——扫描、匹配、统计、格式校验、模式提取、冲突检测 |
| **智能体**（AI） | 所有能做的一切——解读信号、补全文件、修复问题、创建 stub、加实例映射、跑脚本、迭代直到结果干净 |
| **人类** | 看结果、审核、做 AI 明确不能做的组织决策 |

**协作流**：

```
规则引擎 → 信号
          ↘
智能体 → 解读 + 修复 + 补全 → 跑规则引擎 → 再修 → 直到干净
          ↙
人类看最终结果 → 审核 → 偶尔介入组织决策
```

## 规则引擎做什么

| 脚本 | 规则 |
|------|------|
| `validate.sh` | 检查文件存在性 + JSON 合法性 |
| `summary.sh` | 统计本体/实例/关系/文件数 |
| `fusion-check.sh` | 本体名称去空格对比、词汇交叉匹配、引用断裂检测+自动创建 stub、效力主体提取去重 |
| `detect-domain.sh` | 词汇命中计数+排序 |
| `init-domain.sh` | 创建领域目录和骨架文件（四个 JSON），支持 `--from-detect` 自动填充 |
| `find-undefined-terms.sh` | 扫描全库 `**加粗术语**`，对比所有领域已知定义，列出未定义项 |
| `auto-fix.sh` | 循环 validate → 自动修复 JSON 格式和缺失骨架 → 直到全部通过 |

## 智能体做什么

所有能做的一切：

- 批量执行脚本组合（如 `./scripts/detect-domain.sh → init-domain.sh --from-detect`）
- 解读脚本输出，排查根因
- 补充脚本不能自动判断的内容（如 `find-undefined-terms.sh` 输出列表后，判断是否需要在 instances.json 中补充定义）
- 出现效力声明不一致时 → 展示差异 + 分析原因 + 建议统一方向
- 多领域命中接近时 → 列出视角差异 + 附上建议
- 发现深层结构缺口（如全库使用某个术语但无人定义）→ 指出来给人

智能体不做的事：改效力声明主体、消解涉及组织权力的语义分歧。这些留给人类审核时决定。

## 人类做什么

- 看智能体最终交付的结果
- 审核引用断裂的修复建议（接受/拒绝）
- 确认效力声明统一方案
- 批准新领域创建
- 做智能体明确标记"需要人判断"的决策

人类不看中间过程，只看最终交付物和智能体标记的问题。
