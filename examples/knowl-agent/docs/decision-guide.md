# 检测决策指南

## 三分工

| 角色 | 负责 | 不负责 |
|------|------|--------|
| **规则引擎**（scripts/） | 扫描文件、匹配模式、统计计数、格式校验、输出结构化信号 | 解释信号含义、做判断、写结论 |
| **智能体**（AI） | 解读信号、按已知规则决策、自动执行确定性操作、发现异常时提给人 | 越界决策、修改涉及组织权威的内容、创建新领域 |
| **人类** | 做价值判断、确认消歧方案、决定组织设计问题、批准新领域 | 执行重复性检测、修 JSON 格式 |

### 协作流程

```
规则引擎 → 输出信号 ─→ 智能体 → 确定性操作（修格式/补 stub/加映射）
                           → 人类决策（效力主体/语义消歧/新领域）
```

---

## validate.sh

```
./scripts/validate.sh
```

### 输出：JSON 格式错误

```
[FAIL] xxx.json - JSON 格式错误
```

**处理**：AI 自动修复。读取文件修正 JSON 语法（多余的逗号、引号不匹配、括号缺失）。

### 输出：文件缺失

```
[MISS] ontologies.json
```

**处理**：AI 创建空骨架文件。根据该领域 `domain.json` 的内容，按同级领域相同文件的模板结构创建初始内容。

## summary.sh

```
./scripts/summary.sh
```

### 输出：实例数远少于文件数

同一领域中实例数 ÷ 文件数 < 2，说明建模深度不足。

**处理**：AI 检查该领域每个覆盖文件的内容，将遗漏的映射添加到 `instances.json`。凭据是该领域的 ontologies.json 中定义的模式。

### 输出：本体数偏少

某领域的本体数明显少于其他领域（如只有 1-2 个），可能遗漏了反复出现的概念结构。

**处理**：AI 重新扫描该领域的覆盖文件，寻找是否有其他反复出现的模式。如果找到疑似模式但不确定，记录下来让人判断。如果确认是遗漏，直接新增本体和对应实例。

## fusion-check.sh

```
./scripts/fusion-check.sh
```

### 输出：本体名称冲突

```
"权责" 出现在: org-management ←→ legal-normative
```

**处理**：AI 检查两个同名的本体描述是否一致。

- 描述一致 → 同一概念在不同视角下被独立发现。记录为"视角共享概念"，无需处理
- 描述不同 → 同名异义。标给人判断：是否需要统一命名来区分

### 输出：术语交叉引用

```
"资格" 同时属于: hr, org-management
```

**处理**：AI 检查该术语在两个领域的实例中的含义。

- 含义一致 → 不做处理，记录在案
- 含义不一致 → 标给人判断

### 输出：引用断裂

```
xxx.md: 引用 "《量潮数据项目岗位权责章程》" → 期望 qtdata-role-authority.md 但不存在
```

**处理**：AI 判断是否应该存在对应文件。

- 引用的是外部法律文件（《中华人民共和国公司法》等）→ 加入 `IGNORE_LIST`
- 引用的是通用商业概念（《工作订单》《需求规格说明书》等）→ 加入 `IGNORE_LIST`
- 引用的是知识库内应有的文件 → AI 创建 stub 文件，填充基本结构
- 不确定 → 记录给人判断

### 输出：效力声明不一致

```
⚠️ 存在不同的效力主体
```

**处理**：**必须交给人类判断**。效力声明涉及组织的权威层级和生效路径，AI 无权决定采用哪个主体。AI 只展示各文件的差异原文给人看。

## detect-domain.sh

```
./scripts/detect-domain.sh <file>
```

### 输出：单一领域命中显著领先

```
org-management: 命中 41 次
legal-normative: 命中 24 次
（其他 < 10）
```

**处理**：AI 直接按该领域启动建模。创建 `domains/<domain>/domain.json` 并将该文件加入 `files` 列表。

### 输出：多个领域命中接近

```
org-management: 命中 28 次
legal-normative: 命中 25 次
hr: 命中 22 次
```

**处理**：提给人问优先从哪个视角开始。在获得答复前不做选择。

### 输出：所有领域命中都低

```
（全部 < 5 次）
```

**处理**：文件内容可能与已有领域都不匹配。提给人判断是否需要新建领域。AI 可以基于文件中的高频词汇建议新领域的名称和词汇表，但最终的领域定义（perspective + vocabulary）由人确认。

## 无论如何都不能碰的

- **修改效力声明**（章程效力条款的生效主体和路径，涉及组织决策权）
- **判断"公司治理机构"之类的术语是否需要在特定文件中定义**（涉及组织设计决策）
- **决定是否创建新领域**（AI 可以建议，不能决定）
- **消解跨领域的语义冲突**（AI 可以展示差异，不能代替人选择统一方案）

## 直接自动处理的

- **修复 JSON 格式**（括号、引号、逗号）
- **补全引用断裂对应的 stub 文件**（AI 确认是知识库内文件后）
- **添加遗漏的实例映射**（AI 确认 ontologies.json 中有对应模式后）
- **更新 IGNORE_LIST**（AI 确认引用的是外部法律或通用商业概念后）
- **基于 detect-domain 结果创建 domain.json**（命中显著领先时）
