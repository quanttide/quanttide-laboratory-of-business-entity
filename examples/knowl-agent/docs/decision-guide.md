# 三分工

| 角色 | 负责 |
|------|------|
| **规则引擎**（scripts/） | 所有有确定规则的事——扫描、匹配、统计、格式校验、模式提取、冲突检测 |
| **智能体**（AI） | 所有能做的一切——解读信号、补全文件、修复问题、创建 stub、加实例映射、跑脚本、迭代直到结果干净 |
| **人类** | 看结果、审核、做 AI 明确不能做的组织决策 |

**协作流**：

```
规则引擎 → 信号
          ↘
智能体 → 解读 + 修复 + 补全 → 跑规则引擎 → 再修 → 直到干净
          ↙
人类看最终结果 → 审核 → 偶尔介入组织决策
```

## 规则引擎做什么

所有有确定规则的操作：

- `validate.sh` — 检查文件存在性 + JSON 合法性
- `summary.sh` — 统计本体/实例/关系/文件数
- `fusion-check.sh` — 本体名称（去空格后字符串等值比较）、词汇表交叉匹配、引用断裂（《…》提取+名称映射表+IGNORE_LIST）、效力主体（grep 提取+去重计数）
- `detect-domain.sh` — 词汇命中计数+排序

规则引擎不解释、不判断、不修东西。

## 智能体做什么

所有能做的事，不等人类指令：

- 收到 validate.sh FAIL → 读文件修 JSON 语法
- 收到 MISS → 创建骨架文件
- 收到引用断裂 → 判断是外部引用还是内部缺失：外部加入 IGNORE_LIST，内部缺失创建 stub
- 收到术语交叉引用 → 检查两个领域的实例含义：一致则记录，不一致则标给人，但标给人之前先给出分析和建议
- 收到效力声明不一致 → 展示差异，给出分析，建议统一方向
- 收到 detect-domain 结果 → 命中领先直接建 domain.json；命中接近则列出视角差异给人选，但附上建议
- 发现全库使用但未定义的术语 → 指出来给人
- 跑完一轮工具 → 修完问题 → 再跑一轮确认 → 直到全部通过

智能体不做的事：改效力声明主体、消解涉及组织权力的语义分歧。这些留给人类审核时决定。

## 人类做什么

- 看智能体最终交付的结果
- 审核引用断裂的修复建议（接受/拒绝）
- 确认效力声明统一方案
- 批准新领域创建
- 做智能体明确标记"需要人判断"的决策

人类不看中间过程，只看最终交付物和智能体标记的问题。
