# 知识发现与建模方法论

## 核心流程

### 预备：领域发现

扫描知识库，识别所涵盖的知识领域。每个领域代表一个观察视角。

**工具**：`scripts/detect-domain.sh`

```
./scripts/detect-domain.sh sample/<file>
```

扫描新文件，基于领域词汇表匹配命中次数，推荐所属领域。输出按命中次数排序，命中越高说明该领域视角越适合分析此文件。

**产出**：`domains/<domain>/domain.json`

---

### 第一步：本体发现

在每个领域内，找出**反复出现的概念结构**——知识库用哪些固定的思维模板来组织该领域的知识。本体只关心抽象模式，不含具体实例。

**要点**：
- 一个领域下可发现多个本体
- 视角决定看到什么本体，须显式声明当前视角
- 同一事物在不同领域中有不同本体

**产出**：`domains/<domain>/ontologies.json`

---

### 第二步：实例映射

将知识库中的具体内容映射到本体上。

**产出**：`domains/<domain>/instances.json`

---

### 第三步：关系发现

识别跨本体或跨实例的连接。关系是本体的附属，不是独立概念。

**产出**：`domains/<domain>/relations.json`

---

### 第四步：跨领域融合

对比不同领域对同一术语的定义和处理，发现冲突和不一致。

**工具**：`scripts/fusion-check.sh`

```
./scripts/fusion-check.sh
```

扫描所有领域，检测两件事：
1. 不同领域中是否存在同名本体（同一概念结构被不同视角捕获）
2. 同一条术语是否同时出现在多个领域的词汇表中（跨领域术语的可能冲突点）

输出按冲突类型分组。同名本体说明该概念在不同视角下可能有不同含义，需要人判断是否需要保留视角差异还是统一。跨领域词汇重叠说明该术语有多义风险。

**融合不是合并**——不把不同领域拉到同一张图上消解差异，而是保持各领域独立，通过对比暴露差异。

**产出**：`data/fusion-report.json`

---

### 第五步：反馈闭环

融合发现的差异不会自动修复。它暴露给人类，由人判断和补全。补全后的知识库可以再次检测。

**实际案例**：`scripts/fusion-check.sh` 发现效力声明不一致 → 人统一修复 → 发现"公司治理机构"未定义 → 发现基本章程缺失 → 新增基本章程 → 章程体系完整性提升。整个过程由检测驱动，人在缺口处做精确补全。

---

## 质量保障

### 结构完整性

**工具**：`scripts/validate.sh`

```
./scripts/validate.sh [domains/]
```

验证每个领域目录是否包含全部四个必要文件（domain.json / ontologies.json / instances.json / relations.json），并检查 JSON 格式合法性。在新建领域或修改文件后执行。

### 概况总览

**工具**：`scripts/summary.sh`

```
./scripts/summary.sh [domains/]
```

生成概况表，按领域列出本体数、实例数、关系数和覆盖文件数。用于快速了解当前建模进度，判断哪些领域建模深度不足。

---

## 不做什么

- 不做格式级别的检测（标题层级、分隔线数量、用语规范）
- 不做问题追踪和评分（那是人的工作）
- 不将语言模态系统列为领域本体（应当/不得/可以是表达方式，不是概念结构）
- 不试图"统一"不同领域的视角差异——差异本身就是发现

## 目录结构

```
domains/
├── <domain>/
│   ├── domain.json       # 领域清单
│   ├── ontologies.json   # 本体（仅抽象模式）
│   ├── instances.json    # 实例（映射到本体）
│   └── relations.json    # 关系（连接本体和实例）
data/                     # 临时数据和融合报告
scripts/
├── validate.sh           # 结构完整性验证
├── summary.sh            # 概况总览表
├── fusion-check.sh       # 跨领域冲突检测
└── detect-domain.sh      # 新文件领域推荐
docs/                     # 文档
```

## 关键认知

- 本体没有对错，不同视角揭示不同的结构
- 小不一致往往连着大缺口——效力声明用词不统一可能指向根级别的结构缺失
- 人判断是流程的一环，检测不代替人做决定
- 工具不产出结论，只暴露信号
