# 知识发现与建模方法论

## 核心流程

### 预备：领域发现

扫描知识库，识别所涵盖的知识领域。每个领域代表一个观察视角。

**产出**：`domains/<domain>/domain.json`（领域清单）

### 第一步：本体发现

在每个领域内，找出**反复出现的概念结构**——即知识库用哪些固定的思维模板来组织该领域的知识。本体只关心抽象模式，不含具体实例。

**要点**：
- 一个领域下可发现多个本体
- 本体没有对错，但不同视角揭示的结构不同
- 视角须显式化，避免将单视角发现误作唯一真理

**产出**：`domains/<domain>/ontologies.json`

### 第二步：实例映射

将知识库中的具体内容映射到本体上。每条实例标注所属本体、来源文件和位置。

**要点**：
- 实例可以引用多个本体
- 实例可以引用关系

**产出**：`domains/<domain>/instances.json`

### 第三步：关系发现

识别跨本体或跨实例的连接。关系描述实体之间如何关联，不是第一等概念，而是本体的附属。

**要点**：
- 关系是连接，不是独立的概念结构
- 同一关系类型可出现在多个本体之间

**产出**：`domains/<domain>/relations.json`

### 第四步：跨领域融合

对比不同领域对同一术语的定义和处理，发现冲突和不一致。

---

## 不做什么

- 不做格式级别的检测（标题层级、分隔线数量、用语规范）
- 不做问题追踪和评分（那是人的工作，不是检测工具的事）
- 不将语言模态系统列为领域本体（应当/不得/可以 是表达方式，不是概念结构）
- 不将范畴作为独立概念管理（降级为关系）

## 目录结构

```
domains/
├── <domain>/
│   ├── domain.json       # 领域清单：视角、文件、词汇
│   ├── ontologies.json   # 本体（仅抽象模式）
│   ├── instances.json    # 实例（映射到本体）
│   └── relations.json    # 关系（连接本体和实例）
data/                     # 临时中间数据
scripts/                  # 脚本
docs/                     # 文档
```
