# 人机权责清单

## 协作流

```
规则引擎 ──→ 信号
               ↓
         智能体 ──→ 解读 + 修复 + 补全 ──→ 跑规则引擎 → 再修 → 直到干净
               ↓
            人类 ──→ 审核最终结果 + 做组织决策
```

---

## 规则引擎（scripts/）

规则引擎的职责是**在确定性规则下执行操作**——能读能写，但每一步都必须有明确的输入-输出规则，不做需要判断的决策。

| 脚本 | 职责 |
|------|------|
| `validate.sh` | 检查领域目录四个 JSON 文件存在性 + JSON 格式合法性 |
| `summary.sh` | 统计各领域的本体数 / 实例数 / 关系数 / 覆盖文件数，输出概况表 |
| `fusion-check.sh` | 跨领域检测：同名本体冲突、词汇交叉重叠、引用断裂、效力主体一致性 |
| `detect-domain.sh` | 对新文件做词汇命中计数 + 排序，推荐所属领域 |
| `init-domain.sh` | 创建新领域目录和四个骨架 JSON 文件，支持 `--from-detect` 自动填充 |
| `find-undefined-terms.sh` | 扫描全库加粗术语，对比所有领域定义，列出未定义项 |
| `auto-fix.sh` | 循环 validate → 修复缺失骨架文件 → 直到全部通过 |

### 权责

- ✅ 执行确定性规则，读写文件
- ✅ 创建目录和骨架文件
- ✅ 补充缺失的 JSON 骨架文件
- ✅ 在规则确定的条件下修改文件内容（如补逗号、去多余括号、创建 stub）
- ❌ 做需要判断的决策（什么内容放进 stub、术语是真缺口还是假阳性）

---

## 智能体（AI）

智能体的职责是**解读信号并采取行动**——运行脚本、分析输出、修复问题、补全内容，迭代直到结果干净。

### 权责

- ✅ 运行脚本组合（如 `detect-domain.sh → init-domain.sh --from-detect`）
- ✅ 解读脚本输出，排查根因
- ✅ 修复 JSON 格式错误、补充缺少的字段、完善内容
- ✅ 将 `find-undefined-terms.sh` 输出的未定义术语列表，判断是否需要在 instances.json 中补充定义
- ✅ 将 `fusion-check.sh` 检测到的引用断裂，创建 stub 文件或指向已有文件
- ✅ 出现效力声明不一致时，展示差异 + 分析原因 + 建议统一方向
- ✅ 多领域命中接近时，列出视角差异 + 附上建议
- ✅ 发现深层结构缺口（如全库使用某个术语但无人定义），指出来给人类
- ✅ 跑规则引擎验证修复结果，迭代直到干净
- ❌ 不得修改效力声明主体
- ❌ 不得消解涉及组织权力的语义分歧
- ❌ 不得批准新领域创建
- ❌ 不得擅自决定涉及组织架构、权责分配的事项

### 输出规范

- 最终交付物包含：做了什么、没做什么、需要人审什么
- 把拿不准的判断标记为 **【需人确认】**

---

## 人类

人类的职责是**审核与决策**——看最终结果，做智能体不能做的组织决策。

### 权责

- ✅ 审核智能体最终交付的结果
- ✅ 审核引用断裂的修复建议（接受 / 拒绝 / 调整）
- ✅ 确认效力声明统一方案
- ✅ 批准新领域创建
- ✅ 做智能体标记为 **【需人确认】** 的决策
- ✅ 对涉及组织权力、人事、权责对等的语义分歧做最终判断
- ❌ 不看中间过程——只看最终交付物和智能体标记的问题
