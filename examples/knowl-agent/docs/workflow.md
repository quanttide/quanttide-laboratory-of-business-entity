# 知识发现与建模工作流

## 三元分工

参见 `docs/responsibility-matrix.md`：

| 角色 | 擅长 |
|------|------|
| **规则引擎** | 确定规则 —— 固定模式匹配、校验、读写 |
| **智能体** | 概率模式匹配 —— 解读信号、做建议、补全 |
| **人类** | 意义与意外 —— 做组织决策、审核 |

---

## 核心流程

### 预备：领域发现

扫描知识库，识别所涵盖的知识领域。每个领域代表一个观察视角。

**工具** → `scripts/detect-domain.sh`

```
./scripts/detect-domain.sh sample/<file>
```

基于词汇命中排序，推荐最匹配的领域。命中显著领先时规则引擎直接输出推荐；命中接近时智能体分析视角差异给人选。

**产出**：`data/<domain>/domain.json`（规则引擎通过 `init-domain.sh` 创建）

---

### 第一步：本体发现

在每个领域内找出**反复出现的概念结构**——知识库用哪些固定的思维模板来组织知识。本体只关心抽象模式，不含具体实例。

**执行者**：智能体。分析文件内容，归纳模式，写入 `ontologies.json`。

**要点**：
- 一个领域下可发现多个本体
- 视角决定看到什么本体，须显式声明
- 同一事物在不同领域中有不同本体

**产出**：`data/<domain>/ontologies.json`

---

### 第二步：实例映射

将具体内容映射到本体上。

**执行者**：智能体。阅读文件条款，判断每条内容归属的本体。

**产出**：`data/<domain>/instances.json`

---

### 第三步：关系发现

识别跨本体或跨实例的连接。关系是本体的附属。

**执行者**：智能体。

**产出**：`data/<domain>/relations.json`

---

### 第四步：跨领域融合

对比不同领域对同一术语的定义和处理，暴露冲突和不一致。

**工具** → `scripts/fusion-check.sh`

```
./scripts/fusion-check.sh
```

自动检测：同名本体冲突、词汇交叉、引用断裂、效力主体一致性。

**融合不是合并**——不消解差异，保持各领域独立，通过对比暴露信号。

**信号处理**：
- 引用断裂 → 智能体判断是否需创建 stub 或更新 NAME_MAP
- 术语交叉 → 智能体检查含义是否一致，不一致时给人标记 **【需人确认】**
- 效力主体不一致 → 智能体分析差异并建议统一方向，给人决策

**产出**：`data/fusion-report.json`

---

### 第五步：反馈闭环

暴露的缺口不会自动修复。智能体按能力边界处理，需要组织决策的给人。

**辅助工具**：

```
./scripts/validate.sh      # 检查结构完整性
./scripts/summary.sh       # 概况总览
./scripts/find-undefined-terms.sh  # 找出未定义术语
./scripts/auto-fix.sh      # 补缺失骨架文件
```

**迭代模式**：智能体修 → 跑规则引擎验证 → 再修 → 直到 validate 全部通过。

---

## 目录结构

```
data/<domain>/
├── domain.json       # 领域清单
├── ontologies.json   # 本体（仅抽象模式）
├── instances.json    # 实例（映射到本体）
└── relations.json    # 关系（连接本体和实例）
scripts/
├── validate.sh       # 结构完整性验证
├── summary.sh        # 概况总览表
├── fusion-check.sh   # 跨领域冲突检测
├── detect-domain.sh  # 新文件领域推荐
├── init-domain.sh    # 创建新领域骨架
├── find-undefined-terms.sh  # 未定义术语查找
└── auto-fix.sh       # 循环修复
data/                 # 临时数据和融合报告
docs/                 # 文档
```

## 不做什么

- 不做格式级别的检测（标题层级、分隔线数量、用语规范）
- 不做问题追踪和评分（那是人的工作）
- 不将语言模态系统列为领域本体（应当/不得/可以是表达方式，不是概念结构）
- 不试图统一不同领域的视角差异 —— 差异本身就是发现
